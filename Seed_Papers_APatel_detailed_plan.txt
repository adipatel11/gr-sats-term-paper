Proposed project: Group-Robust Shift-Aware Temperature Scaling

Title, target venue, year:

Group-Robust Shift-Aware Temperature Scaling for Adapted Medical Foundation Models Under Image Corruption, targeting the MICCAI 2027 FAIMI or UNSURE workshops.

Research problem:

I've narrowed the project down to one open question and a method to address it. When a medical foundation model is adapted with linear probing, LoRA, or full fine-tuning, does a calibrator fit on clean validation data stay reliable as corruption severity goes up? And does it break down more for some demographic subgroups than for others?

Datasets:

I'll use HAM10000 with sex and age as the sensitive attributes, Fitzpatrick17k with skin type, and CheXpert with sex, age, and race. I'll write a small data loader of my own for the two skin datasets, since HAM10000 needs lesion-level splits and a different label definition from MEDFAIR's (see below). The MEDFAIR and FairMedFM loaders are still useful for CheXpert later. I'll apply the MedMNIST-C corruptions at severities 1 through 5.

For Fitzpatrick17k, I'll use the cleaned version from Abhishek et al. (Fitzpatrick17k-C), which removes duplicates and leaves 11,394 images. It comes with standard training, validation, and test splits of 7,975, 1,139, and 2,280 images, and I'll use those. I'll merge the skin types into three groups (I and II, III and IV, V and VI) so each group has enough samples. Some of the original image links are broken, but Abhishek et al. also host an archive of all 16,577 images, so I don't need to wait on the original authors. I already have the images, but they don't come with labels. Those come from Fitzpatrick17k-C.csv on Abhishek et al.'s Zenodo record (doi 10.5281/zenodo.11101337). It gives each image's split, skin type, and malignant, benign, or non-neoplastic label, and it matches my image files by their MD5 names. The task is malignant versus everything else, meaning benign and non-neoplastic cases together. If I limited it to benign versus malignant, most of the images would be dropped and there would be too few malignant cases left in skin types V and VI.

For HAM10000, the task is malignant (melanoma, basal cell carcinoma, and actinic keratosis or intraepithelial carcinoma) versus benign. I'll split by lesion instead of by image, because some lesions have several near-identical photos. Splitting by image would let those photos end up in both the reference bank and the test set. Abhishek et al.'s DermaMNIST-C already splits HAM10000 by lesion (8,215 training, 573 validation, and 1,227 test images), and its CSV on the same Zenodo record gives each image's lesion, age, sex, and split. So I'll use that split instead of making my own. The images themselves come from the Harvard Dataverse, and their file names match the CSV. MEDFAIR's loader counts basal cell carcinoma as benign, following Maron et al. (2019), but I'm counting it as malignant because it's a skin cancer. That makes about 20% of the images malignant instead of about 14%. MEDFAIR also splits by image, so my numbers won't match theirs either way, and I'd rather keep the clinical definition. I'll say this clearly in the paper's dataset section.

Methodology:

For the core comparison I'll use two ViT-B encoders, DINOv2 and BiomedCLIP, and I'll add an ImageNet-supervised ViT if there's time. Keeping the model size fixed means pretraining is the main thing that differs between them. DINOv2 uses 14-pixel patches instead of 16, but otherwise it's the same size. When I write the methods section, two papers from the Connected Papers graph of FairMedFM can back up these choices. Palés Huix et al. (WACV 2024) found that DINOv2 consistently beat ImageNet pretraining on four medical image classification datasets. Dutt et al. (MIDL 2024) compared 17 parameter-efficient fine-tuning methods on six medical datasets and found them most useful when labeled data is scarce. I've only read their abstracts so far, so I need to read the full papers before citing them.

LVM-Med's released ViT-B is a SAM-style segmentation encoder, so I'll use its ResNet-50 instead, which is also the version FairMedFM uses. I'll compare it against an ImageNet-pretrained ResNet-50 so that this pair also only differs in pretraining.

The core adaptation strategies are linear probing and LoRA. Full fine-tuning comes after the ImageNet ViT if there's still time. CLIP-Adapt will be an extra for BiomedCLIP only, since it needs a text encoder.

I'm calling the method Group-Robust Shift-Aware Temperature Scaling. It's a post-hoc calibrator, so it can be used with any adapted model without retraining. The shift-aware part builds heavily on DAC (ICML 2023).

Each test image gets a shift score, which is the nearest-neighbor distance from its features to a bank of clean training features. I take the log of that distance and standardize it using the mean and standard deviation of the distances for clean validation images. This makes the score unitless, so it can be compared across models. A percentile of the clean distances would be simpler, but it tops out once corruption pushes an image farther away than every clean image, and after that all the higher severities would get the same temperature. None of this needs labels or demographic information at test time.

The inverse temperature is a linear function of the shift score, so there are only two parameters. I clip the shift score to the range seen during fitting so unseen corruptions can't push the temperature out of range. Like in DAC, the reference bank is built from training-set features. Validation and test images never appear in the training set, so a corrupted image is never matched to its own clean copy, and none of the held-out images get used up by the bank. That matters because the smallest groups don't have many images to spare. Fine-tuned models will pull training features closer together than the features of new images, so the standardization uses clean validation images instead of distances among the training images themselves.

The smallest group is the biggest practical problem. The Fitzpatrick17k-C label file shows that skin types V and VI have only 124 validation images (10 cancers) and 238 test images (22 cancers) in the standard splits. The worst-group fit would depend on 10 cancers and the test results on 22, so both would be noisy. To get more out of the data, I'll use cross-fitting. I'll pool the validation and test images and split them into five folds, stratified by group and label. All corrupted copies of an image stay in that image's fold, and for HAM10000 all images of a lesion stay together too. Each calibrator is fit on four folds and tested on the fifth, and the folds rotate until every image has been tested once. That way each fit sees more than twice as many images as the validation set alone, and the final metrics use the whole pool, which is 362 images and 32 cancers in skin types V and VI. Anything learned from data, including the shift-score standardization and every baseline, only uses the four fitting folds. From here on, validation data means the fitting folds and test data means the held-out fold. Because every pooled image ends up as a test image at some point, I won't use the validation split for early stopping. I'll choose the number of training epochs with a small slice of the training split instead.

The two parameters are fit to minimize the NLL of the worst-off demographic group, similar to GroupDRO. DAC puts its linear model on the temperature, but I put mine on the inverse temperature. That makes each group's loss convex in the two parameters, so the worst-group objective is convex too and has a global optimum. Group labels are only used during fitting.

I also constrain the inverse temperature to stay positive at both ends of the clipped range. This only adds two linear constraints, so the problem stays convex, and it means the calibrator can never flip a prediction. With just two parameters, a fine grid search followed by local refinement is enough to fit it.

Raw NLL also reflects how hard a group is to classify, which is a problem for this objective. So I'll test a second version that minimizes each group's excess NLL, meaning how far the group's NLL is above the best NLL it could reach on its own. That keeps the focus on miscalibration and not on how difficult the group is. In the fit, clean images and each severity level will get equal weight. If they didn't, the corrupted copies would outnumber the clean images by about 60 to 1 and the calibrator would mostly ignore the clean data.

Temperature only rescales the logits, so it can't fix a group whose predicted probabilities are too high or too low across the board. That could happen if malignancy rates differ between groups, and they do here. In the pooled Fitzpatrick17k images, about 9% of skin type V and VI images are cancers, compared with 16% for types I and II. If the pilot shows this kind of error, I'll add a bias term that is also linear in the shift score. The loss is still convex with the bias term. Unlike the temperature, though, a bias can push an image across the 0.5 threshold, so this version can change the predicted class. I'd report accuracy and AUC for it, and if it becomes the main version, I'll have to take "never changes the predicted class" out of the abstract.

To test whether the calibrator generalizes, I'll use a leave-one-family-out setup. The calibrator is fit on clean data plus some of the corruption families and then tested on a family it hasn't seen. MedMNIST-C has five corruption families for dermatology (noise, blur, digital, brightness/contrast, and artifacts) and five for chest X-ray (the same first four plus gamma correction), each at five severity levels. The dermatology artifact family (black corners and text overlays) is meant to imitate dermoscope images, so it's less realistic on Fitzpatrick17k's clinical photos. I'll still run that fold, but I'll report it separately for Fitzpatrick17k.

I'll compare the method against these baselines:

- No calibration
- Temperature scaling on clean validation data
- Temperature scaling with out-of-distribution exposure
- Tomani et al.
- DAC
- Atypicality-aware recalibration (AAR)
- Multi-domain temperature scaling
- Cluster-wise temperature scaling in the style of FairCal
- Group-wise temperature scaling

The out-of-distribution exposure version follows Roschewitz et al. (TMLR 2025) and adds a small set of unrelated texture images to the fitting data. I'll fit Tomani et al. twice, once with their original Gaussian noise and once with my training corruption families. Multi-domain temperature scaling will use the training corruption families as its domains. The cluster-wise version runs k-means on the validation features, fits one temperature per cluster, and assigns each test image to its nearest cluster. It's the most direct existing way to target subgroups without test-time group labels. Group-wise temperature scaling uses group labels at test time, but it isn't a strict upper bound because it doesn't adapt to shift. For that reason I'll also report a per-group version of my calibrator as the oracle.

Atypicality-aware recalibration (Yuksekgonul et al., NeurIPS 2023) is the closest existing method, so it's the baseline I most need to beat. It scales the logits by a quadratic function of how atypical an image is and adds a bias for each class. The atypicality score comes from class-conditional Gaussians fit on the training features. On Fitzpatrick17k, with the same three skin-type groups I use, it improved the worst group's calibration and accuracy without using group labels. That was on a nine-class task with a frozen ImageNet ResNet, and it was fit for average NLL and only tested on clean data. My real difference from it is the worst-group objective. To keep the comparison fair, I'll fit AAR on the same clean and corrupted data as my method. I'll also fit AAR's calibrator with my worst-group loss. If that version beats regular AAR too, it shows the gain comes from the objective and not from my shift score.

On top of the baselines, I'll run a 2x2 ablation that crosses global versus shift-aware temperature with average versus worst-group loss. This should show which part of the method is responsible for any improvement. The global temperature with average loss is the same as Tomani et al. fit on my corruption families. That's the kind of simple baseline Roschewitz et al. found hard to beat, so it's the main one my method has to clearly outperform.

For metrics, I'll report NLL, Brier score, and ECE at each severity level, along with the area under the curve of ECE versus severity. For the subgroups, I'll report worst-group NLL, Brier score, and ECE, plus the ECE gap between subgroups. I'll also report NLL and Brier score for every group, not just the worst one. Zietlow et al. (CVPR 2022) found that many fairness methods shrink the gap by making the better-off groups worse, and the per-group numbers will show whether my method does that too. The smallest subgroups will only have a few hundred test images, so binned ECE will be noisy. Because of that, NLL and Brier score will be the main metrics, and I'll compute ECE with equal-mass bins. I'll also report AUC, since a per-image temperature can change AUC even though accuracy stays the same, and accuracy for the methods that can change predictions, like AAR.

Main contribution and expected results:

The main contribution is the objective. DAC and AAR fit their calibrators for average calibration, and mine is fit for the worst-off demographic group instead.

The main test is on unseen corruption families at severity 3 and above, with the held-out families and severities 3 to 5 pooled together. I'm fixing three primary comparisons ahead of time. The first is against the global temperature with average loss, which is Tomani et al. fit on my corruption families and the strongest simple baseline. The second is against DAC, and the third is against AAR, the closest existing method. Against each of them, the method should improve worst-group NLL and Brier score averaged over the 8 core settings (2 datasets, 2 backbones, 2 adaptation strategies), with a 95% paired bootstrap interval that excludes zero. If the extra backbone and full fine-tuning get done, I'll also run the same test over all the settings. The bootstrap will resample source images (lesions for HAM10000) and not individual corrupted copies, because the corrupted versions of one image aren't independent. Requiring a significant win in every setting against every baseline would mean dozens of separate tests. So I'll report per-setting results but rank all the methods across settings with the Friedman and Nemenyi tests from MEDFAIR.

Beyond that, the method should close at least half of the gap to the group-wise oracle. I'll also report average NLL, because fitting for the worst group can cost the other groups, and I want that cost to be visible. On clean data, ECE should stay within 0.01 of standard temperature scaling and AUC should stay within 1 point.

Even if the method underperforms, two secondary findings would still be worth reporting. I'd want to know whether the severity at which clean-fit calibration starts doing harm depends on the adaptation strategy, and whether one calibrator transfers across adaptation strategies or has to be refit for each one. I can only make that second comparison because the shift score is standardized.

If the results hold up, I think this could be a short workshop paper, with CheXpert added before the deadline.

Limitations/gap:

Ovadia et al. (NeurIPS 2019) showed on natural images that calibration gets worse as corruption severity increases, so that part of my question isn't new. Tomani et al. (CVPR 2021) showed that standard post-hoc calibration becomes overconfident under domain shift. Their fix was to calibrate on a validation set perturbed with Gaussian noise at different strengths. That still gives one global temperature tuned for average calibration, and it hasn't been tested on medical corruptions or across subgroups. DAC goes a step further and lets the temperature change for each input. In DAC, the temperature is a weighted sum of k-nearest-neighbor distances from several layers, plus a bias. Multi-domain temperature scaling (NeurIPS 2022) also predicts a per-input temperature from features, but it learns this from several training domains. Both methods optimize average calibration and don't consider demographic subgroups. Cascaded temperature regression (2024) does split samples into subgroups, but by predicted class and confidence rather than by demographic group.

Roschewitz et al. ran a large comparison of calibration methods under real-world dataset shifts, including chest X-ray, retinal, mammography, and pathology tasks. They found that shift-aware methods like DAC often didn't beat simpler post-hoc methods. The most robust calibrators were the ones that saw a small amount of unrelated out-of-distribution data (texture images) during fitting. They didn't look at demographic subgroups. What I took from this is that simple baselines are hard to beat in this setting, which is why my baselines include both simple and shift-aware methods.

On the fairness side, Pleiss et al. (NeurIPS 2017) showed that calibration within each group generally can't be achieved together with equal error rates across groups. So I treat subgroup calibration as the fairness target instead of equalized odds. Liu, Simchowitz, and Hardt (ICML 2019) showed that when group membership can be inferred from the input, ordinary training often ends up calibrated within groups already. On clean images there may not be much left to fix, so the pilot starts with a headroom check.

Atypicality-aware recalibration (NeurIPS 2023) is the closest existing method overall. It changes the temperature for each input based on how atypical the input is, and on Fitzpatrick17k it helped the worst skin-type group without group labels. But it optimizes average NLL and was never tested under shift. FairCal (ICLR 2022) is close in spirit on the fairness side. It improves calibration across groups without test-time group labels by clustering features and calibrating each cluster, but it was built for face verification and doesn't consider shift. Cluster-Focal (MICCAI 2023) reduces calibration error for the worst subgroup. It was only tested on clean data, though, and it requires retraining. CALIN (MICCAI 2025) calibrates at the subgroup level too, but only for multimodal LLMs on clean images. A MELBA 2025 study of skin cancer models looked at calibration across sex, skin tone, and age groups and found calibration problems when the models were applied to new datasets. It only evaluates existing models and doesn't propose a fix. Hekler et al. (AAAI 2023) did propose a fix for skin cancer models at new hospitals. They average the logits over the test image and four augmented copies of it, then apply a calibrator fit on clean validation data, and this lowered NLL and Brier score on melanoma vs. nevus images from New York and Sydney. They didn't look at groups, and their skin cancer shift came from new hospitals, not graded corruptions. Averaging over augmented copies can also change the predicted class, which mine doesn't do. I'm not adding it as a baseline right now, but since it can be put in front of any calibrator, including mine, it would be an easy extension later. Yang et al. (NeurIPS 2023) learn groups from features and logits and fit a calibrator for each group, a lot like FairCal, but they only tested on clean CIFAR and ImageNet. FairDomain (ECCV 2024) studies fairness in eye imaging when the model moves to a different imaging modality, but it measures accuracy and segmentation quality, not calibration. Xu and Daneshjou (AISTATS 2026 calibration workshop) measured GPT-4o's calibration across the same three skin-type groups on the DDI dataset. The darkest group was usually the worst calibrated, but with about 200 images per group, the gap for their main confidence score wasn't statistically significant. They only used clean images and standard or group-wise temperature scaling, so there's no overlap with my method. I couldn't find any work in medical imaging that looks at corruption severity, subgroup calibration, and adaptation strategy together, and that's the gap I want to focus on.

My method has its own limitations too. The calibrator doesn't see group labels at test time, so it can only help the worst group if that group's shift scores differ from the other groups'.

There's also a confound. Groups that are rare in the reference bank, like skin types V and VI, will be farther from it even on clean images, so the shift score partly acts as a stand-in for group membership. That isn't all bad, since it's also how a calibrator without group labels can treat those images differently. It does mean I need to keep two claims apart. Saying that corruption shifts some groups more than others requires removing the confound first. For that, the pilot will check whether the gap in shift scores between groups grows with severity beyond the gap on clean images, and I'll compare against a reference bank with equal numbers from each group. Whether the method helps the worst group doesn't depend on which reason is behind it, so I'll judge the method with the standard bank.

How I would carry it out:

I scaled the plan back again, because as of October 6 I don't have any experiment code yet, and I only just downloaded HAM10000 and the Fitzpatrick17k label file. The pilot grid is now the core result I'm committing to. That's HAM10000 and Fitzpatrick17k, DINOv2 and BiomedCLIP, and linear probing and LoRA, which makes 8 settings. Fitzpatrick17k is in the core because skin type is where corruption is most likely to affect groups differently, for example brightness and contrast changes on darker skin. Sex in HAM10000 is where it's least likely, so HAM10000 will use both sex and age. The ImageNet-supervised ViT and then full fine-tuning only get added if there's time. I also dropped the CheXpert linear-probing backup from the pilot, since getting CheXpert access and setting it up would take time I don't have right now.

This week (October 6 to 11) is for getting the data ready. I've already downloaded the HAM10000 images from the Harvard Dataverse and the two metadata CSVs from Abhishek et al.'s Zenodo record and counted the real group sizes, so what's left is writing the loaders. The next two weeks are for the corruption pipeline and the linear-probing and LoRA runs. The MedMNIST-C library works on my own images, but it needs ImageMagick installed.

The first step after that is a quick headroom check. I'll fit the two-parameter calibrator directly on the pooled images it's evaluated on, once with the average loss and once with the worst-group loss. If the worst-group loss barely helps even there, it can't help on unseen corruptions. After that, the pilot will check whether clean-fit temperature scaling gets worse as severity increases, whether it gets worse unevenly across subgroups, and whether the shift-score gap between subgroups grows with severity. I'll look at per-group reliability diagrams too, to see whether the errors come from overconfidence, which a temperature can fix, or from probabilities that are off in one direction, which would need the bias term. If the headroom check or the shift-score check fails on both datasets, the method has no way to help, and I would fall back on the secondary findings above. I'll make that go/no-go decision by the end of October.

If the pilot passes, I'll run the full method, the baselines, and the ablation on the 8 core settings with 3 seeds and cross-fitting. That's what I'm committing to finish this semester. If it's done early, I'll add the ImageNet-supervised ViT first and full fine-tuning second. CheXpert, the ResNet-50 pair, and CLIP-Adapt would come after the semester.

I estimate the full grid at around 100 GPU-hours, mostly from CheXpert fine-tuning. The dermatology experiments on their own should need roughly 20 to 40, and the core grid less than that, since it skips full fine-tuning. Generating the corrupted images is CPU-bound, but saving all 75 corrupted copies of every pooled image (15 corruptions at 5 severities) as lossless 224-pixel files would take roughly 25 GB for Fitzpatrick17k and about half that for HAM10000. So I won't save them. Each corruption will be seeded by the image, the corruption, and the severity, so the data loader can rebuild exactly the same corrupted image whenever it's needed. During each model's evaluation pass I'll only save what the calibrators need, mainly the logits and the distance and atypicality scores, which comes to tens of megabytes per model. The cost is that the corruptions get regenerated once per model, but that CPU work runs in the data loader workers while the GPU does the forward passes.
